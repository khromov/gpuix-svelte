HOWTO: run from a fresh clone (macOS, Apple Silicon)
====================================================

    bun install     # that's the whole setup.
                    #   @gpuix/native arrives prebuilt from npm (no Rust, no
                    #   submodules, no Metal toolchain, nothing to compile);
                    #   svelte comes from https://pkg.pr.new/svelte@18511, the
                    #   CI preview of the unreleased custom-renderer branch.
    bun run test    # headless: TestGpuixRenderer drives the real Metal
                    # pipeline without opening a window
    bun run demo    # opens all four demo windows at once

    bun run demo:counter     # counter; edit examples/counter/Counter.svelte
                             # and save to hot-reload (content must change —
                             # a bare `touch` does nothing)
    bun run demo:tictactoe   # tic-tac-toe with score tracking
    bun run demo:hn          # Hacker News reader (live data, scrolling)
    bun run demo:glass       # liquid glass: transparent window with
                             # windowBackground "blurred" (macOS vibrancy);
                             # screenshots can't capture the desktop blur,
                             # only the real window shows it

Success looks like:
    [gpuix-svelte] created native window
    [gpuix-svelte] mount complete

Notes
-----
- The `--conditions custom-renderer --conditions development` flags baked into
  every package script are mandatory. Without them svelte's exports resolve to
  its server build and mount() doesn't exist. Always go through `bun run ...`.
- GPUIX_SCREENSHOT=/tmp/x.png bun run demo:counter writes a PNG on every
  (re)mount (use a single demo — all four would overwrite the same file);
  Preview.app reloads on write.
- @gpuix/native is pinned to ^0.5.0 on purpose — 0.6.0 removed the mutation
  contract this renderer uses (commitMutations(), setCustomPropValue, the
  granular methods) and the renderer has not been ported to it. 0.5.x keeps
  the old contract and adds fixes (accurate getWindowSize, sizable test
  viewport width, simulateScrollWheel on the main renderer).
- If pkg.pr.new/svelte@18511 stops resolving, the committed bun.lock keeps
  installs working; only `bun update svelte` needs the URL to be live.
- Optional: bun run test:coverage runs Svelte's own custom-renderer samples if
  SVELTE_SAMPLES_DIR points at a svelte checkout's
  packages/svelte/tests/custom-renderers/samples directory.
