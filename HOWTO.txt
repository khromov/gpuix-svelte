HOWTO: run from a fresh clone (macOS Apple Silicon, Windows x64, Linux x64)
==========================================================================

Needs Node.js 26.1 or newer, or Bun 1.4.0 or newer.

    npm install     # that's the whole setup.
                    #   @gpuix/native arrives prebuilt from npm (no Rust, no
                    #   submodules, no Metal toolchain, nothing to compile);
                    #   svelte comes from vendor/svelte-<version>-<sha>.tgz, a
                    #   build of the unreleased custom-renderer PR (see CLAUDE.md)
    npm test        # headless: TestGpuixRenderer drives the real Metal
                    # pipeline without opening a window
    npm run demo    # opens all four demo windows at once

    npm run demo:counter     # counter; edit examples/counter/Counter.svelte
                             # and save to hot-reload (content must change —
                             # a bare `touch` does nothing)
    npm run demo:tictactoe   # tic-tac-toe with score tracking
    npm run demo:hn          # Hacker News reader (live data, scrolling)
    npm run demo:glass       # liquid glass control center: transparent window
                             # with windowBackground "blurred" (macOS vibrancy)
    npm run demo:glass-ffi   # the same app on REAL Liquid Glass: a tiny ObjC
                             # shim (clang-compiled on first run) slides an
                             # NSGlassEffectView under GPUI's Metal view, loaded
                             # via node:ffi (Node; --experimental-ffi is baked
                             # into the script) or bun:ffi (Bun). Needs macOS 26;
                             # elsewhere it falls back to the window blur.
                             # GPUIX_GLASS=0 forces the fallback. Not part of
                             # `npm run demo`. Note that GPUIX_SCREENSHOT can't
                             # capture either material — only the real window
                             # (or `screencapture`) shows it

Success looks like:
    [gpuix-svelte] created native window
    [gpuix-svelte] mount complete

Notes
-----
- The `--conditions custom-renderer --conditions development` flags baked into
  every package script are mandatory. Without them svelte's exports resolve to
  its server build and mount() doesn't exist. So is `--import ./src/register.js`,
  which installs the .svelte loader. Always go through `npm run ...`.
- GPUIX_SCREENSHOT=/tmp/x.png npm run demo:counter writes a PNG on every
  (re)mount (use a single demo — all four would overwrite the same file);
  Preview.app reloads on write.
- @gpuix/native accepts ">=0.7.0 <=0.8.0" (installs 0.7.0). The renderer
  speaks its contract — applyBatch only, no removeChild op (reinserts
  reparent implicitly; detached nodes are destroyed at commit), setCustomProp
  instead of setCustomPropValue, commitMutations() called only when present.
  Prebuilds exist for darwin-arm64 / linux-x64 / win32-x64 only.
- svelte is a vendored tarball (vendor/svelte-<version>-<sha>.tgz): pkg.pr.new
  stopped building the PR in July 2026, and pkg.svelte.dev drops a build once a
  force-push removes its commit. `npm run vendor` moves it to the current PR
  head.
- Every command has a Bun twin under a `bun:` prefix — npm run bun:test,
  npm run bun:demo, npm run bun:demo:counter, npm run bun:test:coverage.
  Same entry points, run through Bun, which preloads src/plugin.js via
  bunfig.toml instead of taking --import. Dependencies still come from
  npm install either way; CI runs both runtimes.
- npm run compile bundles the tic-tac-toe example into dist/tictactoe
  (dist\tictactoe.exe on Windows) with Bun.build({ compile }); npm run
  compile:app also wraps it as a macOS .app. Bun-only, and built per OS —
  npm installs only the host's prebuilt addon, so there is no cross-compiling.
  Both carry examples/tic-tac-toe/icon.png: an .icns inside the .app, an .ico
  resource in the .exe, cut with sips/iconutil on macOS and PowerShell's
  System.Drawing on Windows.
- Linux runs the demos but not the tests: gpuix compiles TestGpuixRenderer
  only on macOS and Windows (it needs render_to_image, which the Vulkan/wgpu
  backend lacks); on Linux its constructor throws, so the headless suites
  cannot run there.
- Since native 0.7.0 requiresTick() is true everywhere, so the frame loop runs
  on Windows/Linux too (tick() there only polls whether GPUI's UI thread is
  alive). Where it is false the renderer drains its mutation queue on a
  microtask instead — see set_auto_commit() and npm run test:autocommit.
- macOS vibrancy (windowBackground "blurred") is macOS-only. The liquid-glass
  demo asks for plain "transparent" elsewhere and darkens its own panel, so the
  window is still see-through; demo:glass-ffi's non-macOS path does the same.
- npm run demo / npm run bun:demo fan out through scripts/demo-all.js rather
  than a POSIX `&` ... `wait` chain, which cmd.exe does not understand.
- Optional: npm run test:coverage runs Svelte's own custom-renderer samples if
  SVELTE_SAMPLES_DIR points at a svelte checkout's
  packages/svelte/tests/custom-renderers/samples directory.
