Build native desktop apps with Svelte

gpuix-svelte renders your Svelte components into a native window on macOS, Windows and Linux, with no DOM or webview. Your UI shares its process with the whole of Node or Bun: files, processes, SQLite and native addons.

$npm create gpuix-svelte@latest my-app

gpuix-svelte maps ordinary Svelte components onto GPUI, the GPU-accelerated UI framework behind the Zed editor, through Svelte’s unreleased custom renderer API. Your markup, runes and <style> class rules compile as usual.

Quick start

npm start opens a counter in its own window. Edit App.svelte, save, and the window hot-reloads.

You need Node.js 24 or later, or Bun 1.4 or later, on macOS (Apple Silicon), Windows (x64) or Linux (x64). On Bun, run bun create gpuix-svelte my-app, then cd my-app, bun install and bun run start.

$ npm create gpuix-svelte@latest my-app
Created my-app. Next:

  cd my-app
  npm install
  npm start      # opens the window; edit App.svelte to hot-reload
  npm test       # headless test (macOS and Windows)
  npm run build  # standalone executable in dist/ (requires Bun)

How it works

Both paths start from your .svelte file and Svelte’s own compiler. gpuix-svelte runs the compiler with the customRenderer option, so the compiled code builds a tree of plain JavaScript objects, the shadow tree, instead of DOM nodes. Each frame’s changes reach GPUI in one batch.

Hot reload

Save a .svelte file and render_hot remounts the app in the window that’s already open. Component state starts over; state in a .svelte.ts module survives.

	.primary {
		background-color: #a6e3a1;
		color: #1e1e2e;
		background-color: #ff3e00;
		color: #ffffff;
	}

Styling

Scoped <style> blocks take class rules with :hover and :active. Layout is flexbox in logical pixels, and values GPUI can’t use, like em or border-radius: 50%, are dropped with a warning.

Testing

gpuix-svelte/test clicks through GPUI’s real hit testing without opening a window (macOS and Windows only). gpuix-svelte/automation drives a running app’s window from another process.

Shipping

npm run build needs Bun, whichever runtime you develop on, and writes one executable for the OS it runs on: about 90 MB on macOS (Apple Silicon), with Bun and the GPUI addon inside. The shipping docs cover the macOS .app, signing and notarization. The same app also runs in a browser, on GPUI’s WebAssembly build.

The windows and the icon are drawn for this page. The starter’s build doesn’t set an icon.

Different

Elements are GPUI’s
div, text, img, input, textarea, markdown, virtual-list and a few more. Other tags render as a div, with a warning.
Mouse events don’t bubble
They go to the element under the pointer. hitbox="self" on a clickable element lets clicks on its icons and badges reach it. Styling
No bind:
Inputs report through events with the value in the payload, and {@attach} hands you the element. Guide
Keyboard shortcuts
on_window_key('keydown', handler) hears every key, whatever has focus. Guide
Theming
var(--token) in your styles and one set_css_vars() call. A theme switch restyles in one batch. Styling
In the package
Scroller, Portal, Tooltip and Popover, plus helpers for the window, the file picker, file drops and focus. Components

Status and requirements

Experimental: built on Svelte’s custom renderer API, which is still an open pull request (sveltejs/svelte#18511). Expect breaking changes between minor versions. Needs Node.js 24+ or Bun 1.4+, on macOS (Apple Silicon), Windows (x64) or Linux (x64).
