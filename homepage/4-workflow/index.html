Five commands from an empty folder to a desktop app.

gpuix-svelte is a Svelte custom renderer for GPUI, the UI framework behind the Zed editor. Components render into a native window, without a DOM or a webview, in the same process as Node or Bun.

2 3 4 Run

npm start opens the counter in its own window.

npm install is the whole setup, since the GPUI binary comes prebuilt from npm. npm start runs app.ts, where render_hot opens the component in a 640 × 480 window.

app.ts
import { render_hot } from 'gpuix-svelte';

render_hot(new URL('./App.svelte', import.meta.url), {
	title: 'gpuix-svelte starter',
	width: 640,
	height: 480
});

Edit optional

Saving App.svelte remounts the app in the same window.

render_hot re-imports the component in the same process. Component state starts over, so count is back to 0, while state kept in a .svelte.ts module survives the reload. Editing a .ts file, .svelte.ts included, needs a restart.

Test optional

npm test clicks the buttons with no window open.

mount_headless renders the component through Metal or DirectX, and click_test_id goes through GPUI's real hit testing. The test is a plain script with no runner: finish exits 1 if a check fails or the number of checks that ran is wrong. Headless tests run on macOS and Windows; the Linux prebuild has no test renderer.

test.ts
import { mount_headless, click_test_id, all_text, check, finish } from 'gpuix-svelte/test';
import App from './App.svelte';

mount_headless(App, { width: 400, height: 300 });

click_test_id('plus');
click_test_id('plus');
click_test_id('minus');

check('the buttons reached the counter', all_text().includes('1'));
finish('starter', 1);
$ npm test
ok   the buttons reached the counter

starter ok

gpuix-svelte/test also has type, press, hover, wheel, drag, drop_files, screenshot, clock controls and wait_for. Testing docs

Drive optional

A script drives the running window from another process.

gpuix-svelte/automation has a Playwright-style App and Locator, and a driver runs through the bin like a test: npx gpuix-svelte drive.ts. The wire is JSON over the app's stdin and stdout, so any language can drive it. test_app() runs the same script headlessly.

await app.getByText('3 clicks').waitFor();
await app.screenshot({ path: 'counter.png' });
await app.close();

5 Ship

npm run build writes one executable.

Bun compiles the app into dist/app, with the Bun runtime, Svelte and the GPUI addon inside. npm installs only the addon prebuilt for the host, so each platform builds its own binary. Building needs Bun, whichever runtime you develop on.

A signed macOS app

Copy the repository's scripts/compile.ts and point it at your entry. It wraps the binary in a .app with its own icon, signs it with the certificate CODESIGN_IDENTITY names and notarizes it with the notarytool profile in NOTARY_PROFILE. Signing docs

The web build

GPUI also compiles to WebAssembly and paints a WebGPU canvas (WebGL2 as the fallback), so the same components run in a browser with no DOM nodes. Bun builds it. The server must send cross-origin isolation headers, and the wasm is a 19.9 MB download before compression.

Coming from Svelte on the web

Runes, snippets, {#each}, {#if}, {#await}, <svelte:boundary> and .svelte.ts state modules all work as you'd expect, and so do scoped <style> blocks, for class rules.

Elements

They're GPUI's: div, text, img, svg, input, textarea, markdown, virtual-list and a few more. Any other tag renders as a div, with a warning.

Styling

It's CSS text for a flexbox layout in logical pixels: px or rem, and % or auto for sizes. Values GPUI can't use are dropped with a warning. A theme is var(--token) plus one set_css_vars() call.

Styling docs

Events

Mouse events go to the element under the pointer and don't bubble. hitbox="self" lets clicks on a clickable element's decoration reach it. Right and middle clicks are onauxclick.

Event semantics

Inputs

The compiler refuses bind:, so inputs report through events: onchange={(e) => (text = e.value)}. {@attach} hands you the element.

Forms

Keyboard

on_window_key('keydown', handler) hears every key, whatever has focus. Tab moves focus only if you wire it to focus_next().

Status and requirements

Status
Experimental. Svelte's custom renderer API is an open, unmerged pull request, sveltejs/svelte#18511, so each release bundles the exact Svelte build it was tested against. Expect breaking changes between minor versions.
Runtime
Node.js 24 or later, or Bun 1.4 or later. On Bun, start with bun create gpuix-svelte my-app, then cd my-app, bun install and bun run start.
Platforms
macOS (Apple Silicon), Windows (x64) and Linux (x64), with the GPUI binary prebuilt on npm. GPUI paints with Metal on macOS, DirectX on Windows and Vulkan on Linux.
Headless tests
macOS and Windows. The Linux prebuild has no test renderer.
Builds
Standalone executables and the web build need Bun.
Not included
Native OS menus, auto-update and mobile platforms.
Version
0.2.0, released 2026-10-13. Changelog
