Svelte components, drawn by GPUI.

A Svelte custom renderer for GPUI, the UI framework behind the Zed editor: your components open in a native desktop window, with no DOM or webview.

The App.svelte that npm create writes, and its window after two clicks on + (the pointer is still on +, so it shows its :hover colour). Point at a line, or tab into the code and use the arrow keys, to outline its element in the window.

Quick start

A counter opens in its own window. Edit App.svelte, save, and the window hot-reloads.

On Bun, run bun create gpuix-svelte my-app, then cd my-app, bun install and bun run start. You need Node.js 24 or later, or Bun 1.4 or later.

$ npm create gpuix-svelte@latest my-app
$ cd my-app
$ npm install
$ npm start

Hot reload

When you save a .svelte file, render_hot remounts the app in the window that’s already open. Component state starts over, but state kept in a .svelte.ts module survives. Editing a .ts or .svelte.ts file needs a restart.

Styling

Styles are CSS text for a flexbox layout in logical pixels. The renderer expands shorthands into the longhands GPUI has, and drops any value GPUI can’t use, with a warning.

Headless tests

gpuix-svelte/test mounts a component without opening a window, and its helpers click through GPUI’s real hit testing and input pipeline. A test is a plain script, with no test runner.

Headless tests run on macOS and Windows. The Linux prebuild has no test renderer.

Driving a running app

gpuix-svelte/automation launches your app and drives its real window from another process, through a Playwright-style App and Locator. The wire is JSON over the app’s stdin and stdout, so any language can drive it.


import { launch } from 'gpuix-svelte/automation';
 
const app = await launch({ entry: 'examples/counter/main.ts' });
for (let i = 0; i < 3; i++) await app.getByTestId('plus').click();
await app.getByText('3 clicks').waitFor();
await app.screenshot({ path: 'counter.png' });
await app.close();

The script that took the screenshot, minus a cwd option and a short pause.

In a browser

The same component code runs on GPUI compiled to WebAssembly, painting a WebGPU canvas (WebGL2 fallback). Nothing produces DOM nodes. Bun builds it, and the page must be served with these two headers:

Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp

Serve the .wasm file as application/wasm. It’s 19.9 MB uncompressed, so compress it.

Different

Elements are GPUI’s
div, text, img, svg, input, textarea, markdown, virtual-list, canvas and a few more. Any other tag renders as a div, with a warning.
CSS is a subset
Lengths are px or rem, and sizes also take % and auto. em, vh, vw and box-shadow are dropped. Styling
Mouse events don’t bubble
They go to the element under the pointer. hitbox="self" lets a clickable element take clicks on its decoration. Styling
No bind:
Inputs report through events with the value in the payload, and {@attach} hands you the element. Guide
Keyboard shortcuts
on_window_key('keydown', handler) hears every key, whatever has focus. Guide
Theming
var(--token) in your styles and one set_css_vars() call. A theme switch restyles in one batch. Styling
Components in the package
Scroller draws a scrollbar, Portal paints modals, menus and toasts on top, and Tooltip and Popover hang beside a trigger. Components
Window and desktop helpers
Title, fullscreen, file picker and drops, images from raw pixels, focus order, and aria-* that reaches VoiceOver. Guide

Status and requirements

Status
Experimental. gpuix-svelte is built on Svelte’s custom renderer API, which lives on an open pull request (sveltejs/svelte#18511). Each release bundles the exact Svelte build it was tested against, so gpuix-svelte is the only runtime dependency an app adds. Expect breaking changes between minor versions.
Runtime
Node.js 24 or later, or Bun 1.4 or later
Platforms
macOS (Apple Silicon), Windows (x64), Linux (x64). The GPUI binary comes prebuilt from npm, so npm install is the whole setup.
Graphics
Metal on macOS, DirectX on Windows, Vulkan on Linux
Headless tests
macOS and Windows
Executables and the web build
Bun, whichever runtime you develop on
Version
0.2.0, released 2026-10-13, MIT license
